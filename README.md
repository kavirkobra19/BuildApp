# KavirDL

دانلودر اندروید با پردازش لینک روی GitHub Actions و ذخیره فایل در گوشی.

## امکانات

- افزودن چند لینک پشت سر هم و اجرای دانلودها به‌صورت هم‌زمان؛ هر درخواست شناسه مستقل GitHub Actions دارد.
- پنل دانلودهای پایین صفحه با وضعیت هر کار، نوار پیشرفت، درصد هنگام دریافت فایل، لغو و ذخیره.
- نگهداری تاریخچه فایل‌های دریافت‌شده و امکان ذخیره در گالری یا پوشه دلخواه.
- پشتیبانی از YouTube و سایت‌هایی که `yt-dlp` پشتیبانی می‌کند، به‌علاوه Pinterest.
- دریافت فایل خروجی از Release موقت GitHub و پاک‌سازی Release بعد از دریافت.
- آپدیت درون‌برنامه‌ای از آخرین Release همین مخزن: `kavirkobra19/BuildApp`.

## راه‌اندازی یک‌باره

1. این مخزن را در GitHub نگه دارید و در Settings → Actions → General، اجازه اجرای Actions را فعال کنید.
2. در Settings → Developer settings → Personal access tokens یک Fine-grained token بسازید و فقط همین مخزن را انتخاب کنید.
3. دسترسی‌های **Actions: Read and write** و **Contents: Read and write** را فعال کنید.
4. برنامه را باز کنید؛ در تنظیمات، مخزن `kavirkobra19/BuildApp` و توکن را وارد و اتصال را تست کنید.

توکن فقط روی گوشی در SharedPreferences برنامه ذخیره می‌شود و داخل سورس یا فایل‌های GitHub قرار نمی‌گیرد.

## دانلود هم‌زمان چگونه کار می‌کند؟

هر بار زدن دکمه دانلود، برنامه یک شناسه یکتا می‌سازد و `dl.yml` را با همان شناسه اجرا می‌کند. بنابراین چند درخواست مستقل می‌توانند هم‌زمان اجرا شوند. کارت هر درخواست تا پایان در پنل پایین باقی می‌ماند؛ بعد از اتمام، دکمه «ذخیره» فایل‌های همان درخواست را به محل انتخاب‌شده منتقل می‌کند.

درصد دقیق فقط زمانی قابل محاسبه است که فایل از GitHub به گوشی منتقل می‌شود؛ هنگام پردازش ویدیو روی Runner، برنامه وضعیت مرحله‌ای و نوار نامعین نشان می‌دهد، چون GitHub Actions درصد دانلود yt-dlp را به برنامه گزارش نمی‌کند.

## Spotify

لینک Spotify می‌تواند برای شناسایی آهنگ و باز کردن آن در برنامه رسمی استفاده شود، اما Spotify فایل صوتی قابل دانلود عمومی ارائه نمی‌کند. این پروژه DRM یا محدودیت‌های Spotify را دور نمی‌زند و دانلود مستقیم آهنگ‌های محافظت‌شده را انجام نمی‌دهد. برای دریافت فایل صوتی باید از منبعی استفاده شود که دانلود فایل را مجاز کرده باشد.

## ساخت APK

از تب Actions، ورک‌فلوی **Build APK** را اجرا کنید و فیلد `version` را مثلاً `1.1.0` قرار دهید. خروجی APK به‌صورت Artifact منتشر می‌شود و همان اجرا یک GitHub Release با تگ `v1.1.0` می‌سازد. برنامه از همین Release برای بررسی آپدیت استفاده می‌کند.

برای امضای ثابت نسخه‌های انتشار، این Secrets را تنظیم کنید: `KEYSTORE_BASE64`، `KEYSTORE_PASSWORD`، `KEY_ALIAS` و `KEY_PASSWORD`. بدون این Secrets، بیلد با کلید debug انجام می‌شود؛ برای نصب آپدیت روی نسخه قبلی که با کلید دیگری امضا شده باشد، باید کلید امضای یکسان استفاده شود.

## ساختار

- `app/` کد اندروید و رابط کاربری
- `.github/workflows/dl.yml` اجرای مستقل هر درخواست دانلود
- `.github/workflows/build.yml` ساخت APK و انتشار Release
- `.github/scripts/dl.py` موتور yt-dlp و پردازش فایل خروجی

## نکته

از دانلود یا بازنشر محتوایی که اجازه دسترسی یا ذخیره آن را ندارید خودداری کنید.
